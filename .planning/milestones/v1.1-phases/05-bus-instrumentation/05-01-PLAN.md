- Decorate with `@api.model`
- Create mutable context dict: `_debug_ctx = {'trace_id': uuid.uuid4().hex, 'iteration_id': None, 'tool_call_count': 0}`

- **Emit `new_trace`** before entering super() generator: `{'type': 'new_trace', 'trace_id': trace_id, 'agent_name': self.agent_id.name if self.agent_id else None, 'model_name': model, 'instructions': instructions, 'tools': self._ai_debug_serialize_tools(tools, model), 'state_snapshot': self._ai_debug_state_snapshot(tools_context)}`
  - **BUS-03 RAG context note:** The `instructions` parameter IS the system prompt only (from `_get_instructions()`). RAG context (retrieved documents) is injected into the user message parts by `_get_context_input()` in `_generate_next_response`, NOT into `instructions`. Therefore RAG context is available in the `messages` list at loop entry — specifically as context parts in the initial user message. The first `iteration` event's `messages_sent` will contain the full messages list including RAG context. A separate `rag_context` field is not needed in `new_trace` because the data is already captured in iteration payloads. Document this in a code comment on the `instructions` field: `# system prompt only; RAG context is in messages (captured in iteration events)`
- Iterate `super()._run_agentic_loop(...)` generator. For each yielded `item`:
  - If `'tool_calls' in item` or `'final_message' in item` (LLM response received):
    - `iteration_count += 1`
    - `iteration_id = uuid.uuid4().hex`
    - `_debug_ctx['iteration_id'] = iteration_id` (so _handle_tool_calls can reference it)
    - Capture `messages_snapshot = self._ai_debug_strip_binary(list(messages))` — shallow copy of current message history with binary stripped
    - **Emit `iteration`**: `{'type': 'iteration', 'trace_id': trace_id, 'iteration_id': iteration_id, 'iteration_index': iteration_count, 'messages_sent': messages_snapshot, 'raw_response': item.get('metadata'), 'has_tool_calls': 'tool_calls' in item, 'is_final': 'final_message' in item}`
  - `yield item` (preserve generator protocol)
- **Exception handling** (wrap the super() iteration in try/except):
  - In BOTH exception handlers, before emitting `loop_end`, emit a **failed `iteration` event** so the failed iteration appears in the sidebar tree (Phases 6/7 depend on this). Per locked decision: "LLM API failures (network, rate limit, timeout): part of the iteration event with an error field instead of raw_response. Failed iteration still appears in the tree."
    - Emit `iteration`: `{'type': 'iteration', 'trace_id': trace_id, 'iteration_id': uuid.uuid4().hex, 'iteration_index': iteration_count + 1, 'messages_sent': self._ai_debug_strip_binary(list(messages)), 'raw_response': None, 'error': str(e), 'error_type': type(e).__name__, 'has_tool_calls': False, 'is_final': False}`
    - Then emit `loop_end` as before
  - `except UserError as e`: detect `'successive' in str(e).lower()` for `termination_reason='max_iterations'`, else `'error'`. Emit failed `iteration` + `loop_end` with error info, then `raise`
  - `except Exception as e`: `termination_reason='error'`. Emit failed `iteration` + `loop_end`, then `raise`
- **Success path** (after generator exhausts): emit `loop_end` with `termination_reason='success'`
- **`loop_end` payload**: `{'type': 'loop_end', 'trace_id': trace_id, 'termination_reason': reason, 'error': str(e) if error else None, 'iteration_count': iteration_count, 'tool_call_count': _debug_ctx['tool_call_count'], 'duration_ms': int((time.monotonic() - started_at) * 1000)}`

**Override: `_handle_tool_calls(self, tool_calls, tools_by_name, tools_context, record, confirmed_tool_id=None, refuse_all=False)`**
- Retrieve `_debug_ctx = self.env.context.get('_debug_ctx')`. If not present (instrumentation not active), just `yield from super()...` and return early
- Capture `state_before_batch = copy.deepcopy(tools_context.get('state') or {})` BEFORE calling super()
- Iterate over `super()._handle_tool_calls(tool_calls, tools_by_name, tools_context, record, confirmed_tool_id, refuse_all)` generator
- For each yielded `item`:
  - If `item.get('tool_results')`: for each `result_item` in `item['tool_results']`:
    - Extract: `tool_call_data = result_item.get('tool_call', {})`, `tool_name = tool_call_data.get('name')`, `call_id = tool_call_data.get('id')` (LLM's original call ID), `args = tool_call_data.get('args', {})`, `result = result_item.get('result')`, `success = result_item.get('success', True)`
    - Determine error: if `not success`, set `error = result` (the result IS the error message on failure). If `success`, `error = None`
    - Capture `state_after_batch = copy.deepcopy(tools_context.get('state') or {})`
    - Increment: `_debug_ctx['tool_call_count'] += 1`
    - **Emit `tool_call`**: `{'type': 'tool_call', 'trace_id': _debug_ctx['trace_id'], 'iteration_id': _debug_ctx['iteration_id'], 'tool_call_id': uuid.uuid4().hex, 'tool_name': tool_name, 'call_id': call_id, 'args': args, 'result': result, 'success': success, 'error': error, 'state_before': state_before_batch, 'state_after': state_after_batch}`
  - `yield item` (preserve generator protocol — yield ALL items including 'thought', 'tool_confirmation_request', etc.)

**Note on state granularity:** `state_before` captures state before the entire tool batch, `state_after` captures state after the batch completes. This is Option B from research — per-tool granularity would require re-implementing the upstream method body (Option C), which is too tightly coupled for v1.1. The detail panel in Phase 7 can display "state changed by this batch" which is accurate and useful.

**Note on _handle_tool_calls not being @api.model:** Check the upstream signature — `_handle_tool_calls` is a regular method (not @api.model), so `self` is a record instance. The `_debug_ctx` is accessed via `self.env.context` which is set by `with_context` in _run_agentic_loop.
