**Helper methods (private, on the class):**

1. `_is_debug_enabled(self)` — Check `ir.config_parameter` key `ai_debugger.enabled` with default `"True"`. Return `False` if value is in `("False", "false", "0", "")`. This gates all capture (CONF-01).

3. `_debug_safe_context(self)` — Return a dict copy of `self.env.context` with any `models.BaseModel` instances stripped out (replace with their `.id` or `.ids`). This prevents "cursor already closed" errors when the context is used in a separate cursor environment (Pitfall 3 from research).

4. `_debug_write_trace(self, vals)` — Write a trace record using a separate cursor. Pattern:
   ```python
   try:
       with self.env.registry.cursor() as cr:
           env = api.Environment(cr, self.env.uid, self._debug_safe_context())
           trace = env['ai.debug.trace'].create(vals)
           trace_id = trace.id
       return trace_id
   except Exception:
       _logger.warning("ai_debug: failed to write trace", exc_info=True)
       return False
   ```
   Return the trace ID (int) for use in subsequent iteration/tool call writes. Return `False` on failure.

5. `_debug_write_iteration(self, trace_id, vals)` — Same separate cursor pattern for creating an `ai.debug.iteration` record linked to `trace_id`. Return the iteration ID or `False`.

6. `_debug_update_trace(self, trace_id, vals)` — Same separate cursor pattern for writing (browse + write) the trace record with final state, duration, etc.

**Main override — `_run_agentic_loop`:**

Decorate with `@api.model` (CRITICAL: matches the base method's decorator — Pitfall 1).

Signature must match exactly: `def _run_agentic_loop(self, model, instructions, messages, temperature, tools, tools_context, record=None, schema=None, web_grounding=False)`

Logic:
1. **Config check:** If `_is_debug_enabled()` returns False, `yield from super()._run_agentic_loop(...)` and return immediately (no-op passthrough — CONF-01).
2. **Open trace:** Create trace via `_debug_write_trace()` with: `llm_model=model`, `state='running'`, `instructions` and `rag_context` passed via context (set by `_generate_next_response` override — see Task 2). If trace creation failed (`trace_id is False`), fall back to `yield from super()` and return.
3. **Track timing:** `trace_start = time.perf_counter()`, `iteration_index = 0`, `iter_start = time.perf_counter()`.
4. **Generator passthrough:**
   ```python
   try:
       for item in super()._run_agentic_loop(
           model, instructions, messages, temperature, tools,
           tools_context, record, schema, web_grounding
       ):
   ```
5. **At each yield point**, inspect `item` to determine the event type. Based on the research:
   - `'tool_calls' in item` and `'metadata' in item`: An LLM response with tool calls. Snapshot `messages` (CAPT-04: use `self._debug_strip_binaries(list(messages))` — snapshot BEFORE messages list is mutated by subsequent `extend` calls in the base method). Capture `item.get('metadata')` as raw_response (CAPT-05). Write iteration record with `_debug_write_iteration(trace_id, {...})`. Increment `iteration_index`, reset `iter_start`.
   - `'final_message' in item`: Loop completed normally. Write final iteration. Update trace: `state='done'`, `termination_reason='final_message'`, compute `total_duration_ms`, set `iteration_count`. (CAPT-06)
   - `'tool_confirmation_request' in item`: Confirmation pause. Update trace: `state='paused'`, `termination_reason='confirmation_pause'`. (CAPT-06, CAPT-10)
   - Other items: Pass through unchanged.
   - **Always `yield item`** after capture — the consumer MUST receive every item (streaming behavior unchanged).
6. **After loop exhausts without final_message** (max iterations): Update trace with `termination_reason='max_iterations'`, `state='done'`.
7. **Exception handling:**
   ```python
   except Exception as e:
       self._debug_update_trace(trace_id, {
           'state': 'error',
           'error_message': str(e),
           'total_duration_ms': round((time.perf_counter() - trace_start) * 1000),
           'iteration_count': iteration_index,
       })
       raise  # Re-raise — loop behavior unchanged (CAPT-08)
   ```

**CAPT-07 timing:** Use `time.perf_counter()` for all timing. Multiply by 1000 and round for integer milliseconds. Timing captured at: trace level (trace_start to close), iteration level (iter_start to next yield), tool call level (handled in Task 2's `_handle_tool_calls` override).

**Key constraint:** The `messages` list is mutated in-place by the base method (Pitfall 2). Snapshot it with `list(messages)` or `copy.copy(messages)` at the START of each iteration before `get_completions()` modifies it. Since we intercept at yield points (which is AFTER the messages list has been extended), we need to snapshot the messages array at the point of yield. The yield payload's `metadata` contains the formatted request — use that as the authoritative record if available, otherwise store the messages list state at yield time.
