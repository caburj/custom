Create a NEW file `ai_debug/static/src/app/app.dark.scss`. This file is compiled ONLY in the dark bundle where `web.dark_mode_variables` has already set the dark `$o-*` values.

Per locked decision: match Odoo's own ace editor color scheme for dark mode syntax highlighting.

Contents (dark-only overrides — colors that differ from the light-mode baseline in app.scss):

```scss
// Dark-mode syntax highlighting overrides
// This file is excluded from ai_debug.assets (light) and included in
// ai_debug.assets_dark AFTER web.dark_mode_variables, so all $o-* vars
// resolve to their dark values.

// JSON key (light uses $o-action which is fine in dark too, but override for explicitness)
.ai-json-key    { color: $o-action; }

// JSON string
.ai-json-string { color: $o-success; }

// JSON number (light uses $o-gray-700 for readability; dark uses $o-warning for warm contrast)
.ai-json-number { color: $o-warning; }

// JSON boolean
.ai-json-boolean { color: $o-main-code-color; }

// JSON null/undefined
.ai-json-null   { color: $o-gray-500; font-style: italic; }
```

Key points:
- ONLY color overrides go here. No layout, no sizing, no spacing.
- The `.ai-json-number` override is the main difference: light mode uses `$o-gray-700` (neutral) while dark mode uses `$o-warning` (#FBB56A — warm amber/peach for contrast on dark background).
- Other syntax colors use the same variable names but they compile to DIFFERENT values in the dark bundle (e.g., `$o-action` = #017e84 in light, #02c7b5 in dark).

**Part A: Update manifest for dark.scss exclusion/inclusion**

Modify `ai_debug/__manifest__.py` to follow the web_gantt pattern (verified in 09-RESEARCH.md Open Questions section 3):

In `ai_debug.assets`, add the SCSS glob FIRST, then remove dark.scss files:
```python
'ai_debug.assets': [
    ('include', 'web.assets_backend'),
    'ai_debug/static/src/app/**/*.scss',
    ('remove', 'ai_debug/static/src/app/**/*.dark.scss'),
    'ai_debug/static/src/app/**/*.xml',
    'ai_debug/static/src/app/**/*.js',
],
```

In `ai_debug.assets_dark`, add the dark.scss file AFTER web.dark_mode_variables:
```python
'ai_debug.assets_dark': [
    ('include', 'ai_debug.assets'),
    ('include', 'web.dark_mode_variables'),
    'ai_debug/static/src/app/**/*.dark.scss',
],
```

**CRITICAL ordering rules (from research):**
1. In `ai_debug.assets`: The `('remove', ...)` MUST come AFTER the `'**/*.scss'` glob (remove applies to previously added files)
2. In `ai_debug.assets_dark`: The `'**/*.dark.scss'` MUST come AFTER `('include', 'web.dark_mode_variables')` so dark variables are set before dark SCSS compiles

**Part B: Migrate error banners to Bootstrap alerts**

In `ai_debug/static/src/app/detail/iter_detail.xml`, change:
```xml
<!-- Before -->
<div t-if="props.iteration.error" class="ai-detail-error-banner">
    <span>Error:</span> <t t-esc="props.iteration.error"/>
</div>

<!-- After -->
<div t-if="props.iteration.error" class="alert alert-danger mb-0 rounded-0 border-start-0 border-end-0 py-2 px-3">
    <strong>Error:</strong> <t t-esc="props.iteration.error"/>
</div>
```

In `ai_debug/static/src/app/detail/tc_detail.xml`, change the same pattern:
```xml
<!-- Before -->

</div>

<!-- After -->

</div>
```

The Bootstrap utility classes:
- `alert alert-danger`: Odoo/Bootstrap danger alert (red-tinted bg, red border, red text — auto-adapts to dark mode)
- `mb-0`: No bottom margin (it's between header and notebook)
- `rounded-0`: No border-radius (full-width banner, not a card)
- `border-start-0 border-end-0`: Remove left/right borders for full-width look
- `py-2 px-3`: Compact padding matching the original 8px/16px
- `<strong>` instead of `<span>` for the "Error:" label (semantic + bold without extra CSS)
