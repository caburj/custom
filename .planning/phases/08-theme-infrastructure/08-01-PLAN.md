**1. Controller (`ai_debug/controllers/main.py`) — INFRA-01:**

Replace the two-step `session_info` pattern with `webclient_rendering_context()`:

```python
# REPLACE THIS:
session_info = request.env['ir.http'].session_info()
return request.render('ai_debug.index', {
    'session_info': session_info,
})

# WITH THIS:
context = request.env['ir.http'].webclient_rendering_context()
return request.render('ai_debug.index', context)
```

`webclient_rendering_context()` returns `{'color_scheme': str, 'session_info': dict}`, so `session_info` is still available as a top-level template variable (no breakage). Keep `readonly=True` on the route — the method is read-only by design.

**2. Manifest (`ai_debug/__manifest__.py`) — INFRA-03:**

Add the `ai_debug.assets_dark` bundle to the `'assets'` dict, AFTER the existing `ai_debug.assets` entry. Bump version to `'1.2'`.

```python
'ai_debug.assets_dark': [
    ('include', 'web.dark_mode_variables'),
    ('include', 'ai_debug.assets'),
],
```

This bundle includes `web.dark_mode_variables` (enterprise dark SCSS variable overrides) before the full app bundle. No dark SCSS overrides yet — Phase 9 adds those. Do NOT include `web.assets_backend` directly — it strips `*.dark.scss` files and would undo the dark variables.

**3. Template (`ai_debug/views/ai_debug_index.xml`) — INFRA-02:**

Replace the single `<t t-call-assets="ai_debug.assets"/>` line with the split JS/CSS pattern:

```xml
<!-- JS-only, always loaded -->
<t t-call-assets="ai_debug.assets" t-css="false"/>
<!-- CSS-only, scheme-conditional -->
<t t-if="color_scheme == 'dark'">
    <t t-call-assets="ai_debug.assets_dark" media="screen" t-js="false"/>
</t>
<t t-else="">
    <t t-call-assets="ai_debug.assets" media="screen" t-js="false"/>
</t>
```

Critical details:
- `t-css="false"` on the first call emits only `<script>` tags (JS loaded once)
- `t-js="false"` on conditional calls emits only `<link>` tags (CSS loaded once, from whichever bundle)
- `media="screen"` prevents print media double-loading (matches Odoo pattern)
- `t-else` is required — without it, light mode would get NO CSS at all
- When `color_scheme` is missing/falsy (no cookie), the `t-else` branch fires, loading light CSS (per user decision: no explicit fallback logic needed)

**Anti-patterns to avoid:**
- Do NOT call `session_info()` directly in the controller — loses `color_scheme` key
- Do NOT omit `t-js="false"` on the dark bundle load — would double-load all JS
- Do NOT use `request.httprequest.cookies.get('color_scheme')` — bypasses the `ir.http.color_scheme()` resolution chain
