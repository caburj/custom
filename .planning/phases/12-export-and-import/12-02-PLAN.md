**import_dialog.js:**
```javascript
/** @odoo-module **/
import { Component } from "@odoo/owl";
import { Dialog } from "@web/core/dialog/dialog";

export class ImportPreviewDialog extends Component {
    static template = "ai_debug.ImportPreviewDialog";
    static components = { Dialog };
    static props = {
        traceCount: Number,
        duplicateCount: Number,
        onConfirm: Function,
        close: Function,        // Injected by dialog service
        errorMessage: { type: String, optional: true },
    };
}
```

No setup() needed — this is a pure display component with no lifecycle hooks.

**import_dialog.xml:**
```xml
<?xml version="1.0" encoding="UTF-8"?>
<templates xml:space="preserve">

<t t-name="ai_debug.ImportPreviewDialog">
    <Dialog title="'Import Traces'" size="'sm'">
        <t t-set-slot="default">
            <t t-if="props.errorMessage">
                <p class="text-danger mb-0" t-esc="props.errorMessage"/>
            </t>
            <t t-else="">
                <p class="mb-0">
                    <strong t-esc="props.traceCount"/> trace(s) found.
                    <t t-if="props.duplicateCount > 0">
                        <br/><strong t-esc="props.duplicateCount"/> duplicate(s) will be overwritten.
                    </t>
                </p>
            </t>
        </t>
        <t t-set-slot="footer">
            <t t-if="!props.errorMessage">
                <button class="btn btn-primary"
                        t-on-click="() => { props.onConfirm(); props.close(); }">
                    Import
                </button>
            </t>
            <button class="btn btn-secondary" t-on-click="props.close">Cancel</button>
        </t>
    </Dialog>
</t>

</templates>
```

Design rationale:
- `text-danger` is a Bootstrap class already available in Odoo — renders error text in red without custom SCSS.
- When `errorMessage` is present, only the Cancel button appears (no Import button) — locked decision: errors are inline, no mutation allowed.
- When no error, the dialog shows trace count and duplicate count — locked decision from CONTEXT.md ("12 traces found, 3 duplicates will be overwritten").
- `onConfirm` is called THEN `close()` is called — this matches the OWL Dialog pattern where close() removes the overlay.
- `size="'sm'"` keeps the dialog compact — it's just a confirmation, not a data display.
- No custom SCSS needed — Bootstrap classes (`btn-primary`, `btn-secondary`, `text-danger`) handle all styling.

3. Add the following methods to `AiDebugApp` class, after `deleteCheckedTraces()` and `exportSelected()`:

   ```javascript
   openImportPicker() {
       if (!this.fileInputRef.el) return;
       this.fileInputRef.el.click();
   }

   async onFileSelected(ev) {
       const file = ev.target.files[0];
       if (!file) return;
       ev.target.value = "";  // Reset so re-selecting same file triggers change event
       const text = await file.text();
       this._handleImportFile(text);
   }

   _handleImportFile(text) {
       let parsed;
       try {
           parsed = JSON.parse(text);
       } catch {
           if (this.dialog) {
               this.dialog.add(ImportPreviewDialog, {
                   traceCount: 0,
                   duplicateCount: 0,
                   onConfirm: () => {},
                   errorMessage: "Invalid file: could not parse JSON.",
               });
           }
           return;
       }

       // Validate: must be an array
       if (!Array.isArray(parsed)) {
           if (this.dialog) {
               this.dialog.add(ImportPreviewDialog, {
                   traceCount: 0,
                   duplicateCount: 0,
                   onConfirm: () => {},
                   errorMessage: "Invalid file: expected a JSON array of traces.",
               });
           }
           return;
       }

       // Validate each element: must have trace_id (string) and iterations (array)
       for (const item of parsed) {
           if (
               !item ||
               typeof item !== "object" ||
               typeof item.trace_id !== "string" ||
               !item.trace_id ||
               !Array.isArray(item.iterations)
           ) {
               if (this.dialog) {
                   this.dialog.add(ImportPreviewDialog, {
                       traceCount: 0,
                       duplicateCount: 0,
                       onConfirm: () => {},
                       errorMessage: "Invalid file: each trace must have a trace_id string and iterations array.",
                   });
               }
               return;
           }
       }

       // Count duplicates (traces with same ID already in store)
       const duplicateCount = parsed.filter((r) => this.traces.has(r.trace_id)).length;

       if (this.dialog) {
           this.dialog.add(ImportPreviewDialog, {
               traceCount: parsed.length,
               duplicateCount,
               onConfirm: () => this._applyImport(parsed),
           });
       }
   }

   _applyImport(records) {
       for (const record of records) {
           const hydrated = hydrateTrace(record);
           this.traces.set(record.trace_id, hydrated);
           // Fire-and-forget IDB write — overwrites if duplicate (same pattern as _onLoopEnd)
           if (!this.state.ephemeralMode) {
               writeTrace(hydrated).catch((err) => {
                   console.warn("[ai_debug] IDB write failed during import:", err);
               });
           }
       }
   }
   ```

Key design rationale:
- `file.text()` returns a Promise — cleaner than FileReader callbacks, supported in all modern browsers.
- `ev.target.value = ""` resets the file input immediately so selecting the same file again fires the change event (Pitfall 5 from research).
- All-or-nothing validation: if ANY element fails validation, the entire import is rejected (locked decision). The validation loop returns early on first failure.
- Validation checks the minimum fields required by `hydrateTrace()`: `trace_id` (non-empty string) and `iterations` (array). This is permissive enough to accept files from future versions with extra fields (Pitfall 3 from research).
- `_applyImport()` calls `hydrateTrace(record)` THEN `writeTrace(hydrated)` — never `writeTrace(record)` directly, because raw import records have `iterations` as arrays not Maps, and `writeTrace()` -> `serializeTrace()` calls `.entries()` which requires a Map (Pitfall 4 from research).
- No success toast — the sidebar updating with new traces is the feedback (locked decision from CONTEXT.md).
- Duplicate handling: `this.traces.set(record.trace_id, hydrated)` overwrites if the ID already exists (locked decision: overwrite duplicates).
