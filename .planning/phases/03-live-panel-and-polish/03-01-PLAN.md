**ai_debug/models/ai_session.py:**
- Modify `_debug_write_trace` to also read back the `bus_channel` field from the newly created trace and return it as a tuple `(trace_id, bus_channel)` instead of just `trace_id`. On failure, return `(False, False)`.
- Update all callers of `_debug_write_trace` in `_run_agentic_loop`: change `trace_id = self._debug_write_trace(...)` to `trace_id, bus_channel = self._debug_write_trace(...)` and store `bus_channel` in `debug_ctx`: `debug_ctx = {'trace_id': trace_id, 'iteration_id': None, 'bus_channel': bus_channel}`.
- Add a helper method `_debug_bus_send(self, env, event_type, payload)` that sends a bus notification if `bus_channel` is available in `debug_ctx`:
  ```python
  def _debug_bus_send(self, env, event_type, payload):
      bus_channel = self.env.context.get('_debug_ctx', {}).get('bus_channel')
      if bus_channel:
          try:
              env['bus.bus']._sendone(f'ai_debug:trace:{bus_channel}', event_type, payload)
          except Exception:
              _logger.warning('ai_debug: failed to send bus notification', exc_info=True)
  ```
- In `_debug_write_iteration`: after creating the iteration record, call `self._debug_bus_send(env, 'ai_debug/iteration', {...})` with summary payload: `iteration_id`, `index`, `duration_ms`, `tool_call_count` (0 initially). The `env` from the separate cursor block must be used (NOT `self.env`).
- In `_debug_write_tool_call`: after creating the tool call record, call `self._debug_bus_send(env, 'ai_debug/tool_call', {...})` with summary payload: `tool_call_id`, `iteration_id`, `tool_name`, `duration_ms`, `success`.
- In `_debug_update_trace`: after writing the trace update, call `self._debug_bus_send(env, 'ai_debug/trace_update', {...})` with payload: `trace_id`, `state` (from vals), `termination_reason` (from vals if present), `iteration_count` (from vals if present).
- CRITICAL: All `_sendone` calls must happen INSIDE the `with self.env.registry.cursor() as cr:` block, using the `env` created from that cursor. This ensures the pg_notify fires when the separate cursor commits. Calling `_sendone` on `self.env` (the main cursor) would delay notifications until the HTTP response completes.
- CRITICAL: Bus notification payloads must be small (summary only). Do NOT include messages_sent, raw_response, state_before, state_after in the bus payload. The frontend will RPC-fetch full detail when a user expands an iteration.
